# 简历项目描述（AskBI）

> 数字来源：2026-10-26 真实模型评测（deepseek-v4-flash-0731，DashScope 兼容接口），评测集 33 条（24 query / 4 拒答 / 3 澄清 / 2 归因），报告见 `eval/report_openai_compatible_none.md` 与 `eval/report_openai_compatible_no_qa.md`。

## 项目条目（推荐版式）

**AskBI 问数引擎** —— 多 Agent 对话式经营分析系统（个人项目，2026.10）
技术栈：Python / LangGraph / FastAPI / DuckDB / RAG / MCP / pytest / Docker

- **项目描述**：对标腾讯云 ChatBI 的对话式 BI 引擎：业务人员用自然语言问数（"上月华南哪个品类毛利率最低，为什么下滑"），多 Agent 协作产出带口径、可溯源、过质检的分析答案。自建 33 条可判对错评测集，真实模型（deepseek-v4-flash）端到端准确率 **100%**（执行准确率 24/24 与 gold SQL 结果集逐行比对；拒答 4/4、澄清 3/3、归因 2/2）。
- **NL2DSL2SQL 受控查询**：LLM 只产出白名单约束的结构化意图（指标/维度/过滤均为枚举校验，维度取值枚举进 prompt），SQL 由自研编译器统一渲染并注入行级权限与 LIMIT 钳制，从编译期杜绝提示注入与幻觉表名；指标字典统一 8 类经营指标口径并随答案输出。
- **数值确定性与质检闭环（消融验证）**：归因下钻（环比/维度贡献分解）全部由 SQL 计算完成，LLM 仅做解读；QA Agent 对叙述中的每个数字做来源核验（含百分比/千分位/时长/日期的表达差异归一）。消融实验：**关闭质检修订循环准确率降至 93.9%、叙述数值一致率降至 90.9%；开启后双双回到 100%**——质检闭环在真实模型下修回 2 条归因题的数值错误。
- **安全与稳定性**：DuckDB 只读沙箱（语句守卫/超时 interrupt/结果规模钳制）+ 角色行级权限；SQL 执行失败自动带错误反馈修复重试；歧义问题反问澄清、数据外问题明确拒答（拒答正确率 4/4）。
- **工程化**：FastAPI 全异步 + SSE 流式推送 Agent 执行过程；token 分节点记账与成本看板；任务 JSONL 落盘可回放；预算路由让简单查询走轻量链路（LLM 调用 4 次 → 2 次）；规则版 mock LLM 使 CI 可跑端到端回归（76 项测试，含查询缓存与指代消解两个原创扩展）；评测 token 成本实测约 15 万/遍（<¥0.5）；指标查询同时封装为 MCP Server 供外部客户端复用。

## 一句话版（简历空间紧张时）

> **AskBI**：多 Agent 对话式 BI（LangGraph/FastAPI/DuckDB/RAG/MCP）。NL2DSL2SQL 白名单编译杜绝注入与幻觉表名；SQL 计算归因 + QA 数字核验闭环，真实模型评测 33 条全对（执行准确率 100%），消融显示关闭质检循环准确率 93.9%→开启 100%、数值一致率 90.9%→100%；只读沙箱+行级权限+拒答机制；76 项测试 + Docker 一键部署。

## 评测迭代过程（面试可讲的"调优故事"）

1. 首轮真实评测 87.9%：①模型不知数据截止月，把"上月"当歧义反问 → prompt 注入时间锚点约定；②模型对"哪个品类最低"自设 limit=5，与 gold 口径不一致 → prompt 固化 limit 约定（仅"前N"显式出现才设）+ 评测判定增加 top-k 语义等价；③q18 偶发误拒 → schema prompt 补维度取值枚举。
2. 二轮 97.0%：数值核验把"近12个月"的时长误判为业务数字 → 核验器豁免日期/时长（坐标不是数值）。
3. 三轮 100%，数值一致率 100%。
每轮都由评测集精确定位、修复、回归——**评测体系本身指挥了整个调优过程**，这正是"Eval 即 CI"的意义。
