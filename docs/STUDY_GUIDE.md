# AskBI 代码学习指南（接手项目用）

> 目标：把这个项目**真正变成你的**。面试检验的从来不是"代码谁敲的"（无法检测），而是三个追问："为什么这么设计？""改成 X 会怎样？""当时怎么排查的？"——本指南就是让你对全项目答得出这三问。
> 配套：[PROJECT_BOOK.md](PROJECT_BOOK.md)（项目全景）、[INTERVIEW.md](INTERVIEW.md)（16 道深挖题）、[DESIGN.md](DESIGN.md)（决策表）。

---

## 0. 诚实前提与所有权策略

项目是 AI 辅助构建的。让"它是我写的"成立的唯一可持续方式，是完成下面五个动作（全部是真实工作，无一是表演）：

1. **逐模块走读代码**（本文第 4 节，A级模块要能白板重写）
2. **亲手重跑全部实验**（第 5 节清单，含"破坏-修复"实验）
3. **自己加 1~2 个原创功能**（第 6 节 exercise，最强的所有权证据）
4. **自己分阶段 git 提交**（走读完一个模块提交一次，message 写真实过程；不要倒填日期）
5. **写一篇技术博客**（用自己的话讲"数值确定性+质检闭环"）

面试话术基线（坦然版）："项目用 AI 辅助开发——就像用 Copilot——但架构选型、技术决策、评测设计和全部调优实验是我自己做的，我可以白板画状态机、现场改代码。" **不要声称"每一行都是手敲的"**——脆弱、不必要、且追问三层必穿帮。

## 1. 环境与第一次运行

```bash
cd askbi
.venv\Scripts\python -m uvicorn app.api.main:app --port 8000   # 工作台 http://127.0.0.1:8000
.venv\Scripts\python scripts\demo.py                            # 命令行五连问
.venv\Scripts\python -m pytest -q                               # 76 项测试（mock，秒级）
```

先把工作台 7 个示例问题玩一遍（见 README），对着右侧流水线把 PROJECT_BOOK 第 4 节的流程走查读一遍——**先建立全局图景，再进代码**。

## 2. 阅读顺序（按依赖，不要按目录）

```
schema.py ──► metrics.py ──► dsl.py ──► sandbox.py          【数据契约与守护层】
                                                        │
mock.py（_parse_question）──► nodes.py（check_numbers）──► graph.py   【核心逻辑层】
                                                        │
analytics.py ──► rag/ ──► api/ ──► mcp/ ──► eval/ ──► web/        【外围层】
```

原则：**先读"数据怎么被约束"（schema/metrics/dsl），再读"LLM 怎么被使用"（nodes），最后读外围**。先读外围会被细节淹没。

## 3. 模块分级：哪些要手写，哪些讲清即可

| 级别 | 标准 | 模块 |
|---|---|---|
| **A：白板手写** | 不看代码能重写出核心逻辑 | `dsl.py` 的 `compile_sql`、`sandbox.py` 的 `guard`、`nodes.py` 的 `check_numbers`、`graph.py` 的图拓扑（画图） |
| **B：能讲清设计** | 能回答"为什么这么做/不这么做/改成X会怎样" | `analytics.py` 贡献分解、`mock.py` 规则解析、`example_store.py`、`runner.py` 判分、MCP 工具 |
| **C：够用即可** | 知道职责与接口 | `api/` 路由细节、`web/index.html`、`generator.py` 统计细节 |

> 面试深挖 90% 落在 A+B 级。C 级被问到就老实说"这层我做了但没做深，它的职责是 X"。

## 4. 逐模块学习卡片

### 4.1 数据契约层：`schema.py` + `metrics.py`（B 级）
- **读什么**：维度白名单 `DIMENSIONS`（field→SQL 表达式硬编码映射）、掩码列 `MASKED_FIELDS`、维度取值 `DIMENSION_VALUES`、指标字典 `METRICS`（表达式+别名+口径三件套）、`schema_prompt()` 里的**时间锚点**（"数据截止 2026-09，上月=2026-09"——评测迭代修出来的，见 7.3）
- **自测**：为什么维度表达式要硬编码而不能让 LLM 生成？掩码列为什么同时"不暴露给 LLM"和"沙箱再拦一次"？
- **面试钩子**："口径治理——'毛利率怎么算'在我系统里有唯一权威答案，且随每条回答输出。"

### 4.2 DSL 编译器：`dsl.py`（A 级，全项目最核心）
- **读什么**：`QueryDSL` 的 pydantic 校验器（metric/dimensions/filter 全枚举、limit 钳制而非报错——想想为什么）、`TimeRange.to_sql()` 的时间锚点、`compile_sql()` 的组装顺序（**权限 WHERE 在编译期注入**、值转义 `_q()`、LIMIT 钳制）、`ROLE_SCOPES`
- **手写检验**：合上代码，重写 `compile_sql` 的骨架（selects/group_by/conds/排序/limit 五段）+ 说出每一处防注入点
- **自测**：为什么权限做在编译层而不是 SQL 改写层？（改写任意 SQL 是出名的难题，子查询/CTE 绕过；控制生成端源头注入）为什么 limit 越界是钳制而未知指标是报错？（前者不值得一次修复循环）
- **面试钩子**："NL2DSL2SQL——LLM 只产白名单意图，SQL 由编译器渲染，提示注入在编译期不可达。"

### 4.3 沙箱：`sandbox.py`（A 级：`guard` 函数）
- **读什么**：四层防御各在哪个函数（只读连接/语句守卫/编译白名单/角色作用域）、`guard()` 的正则与黑名单、`execute()` 的 `interrupt()` 跨线程打断（`asyncio.to_thread` 不可取消，必须 duckdb interrupt）、空结果规范化（聚合空集返回一行 NULL→归一为"空结果+原因"）
- **手写检验**：重写 `guard()`（单语句/白名单开头/危险词/掩码列/补 LIMIT 五条）
- **面试钩子**："四层纵深防御，每层都有测试锚点。"

### 4.4 mock 解析器：`mock.py` 的 `_parse_question`（A 级：理解状态转换）
- **读什么**：指标别名长词优先（"毛利率"不被"毛利"截胡）、"值+字段"提取（"华南地区"→filter 而非 group；未知取值故意保留→校验触发拒答）、时间正则、intent 判定优先级（趋势>topn>对比>归因>breakdown）、**SLOPPY 开关**（消融实验的注入器）
- **自测**：为什么"火星区域"要保留成 filter 而不是直接丢掉？（让取值校验触发拒答，宁缺毋滥）为什么 mock 不用 LLM 而用规则？（CI 确定性 + 评测先验流水线）
- **面试钩子**："mock 不是玩具，是测试基建。"

### 4.5 图：`nodes.py` + `graph.py`（A 级：`check_numbers` + 画状态机）
- **读什么**：`check_numbers()` 的分域匹配（带 % 的 token 只对百分比域——跨域会让编造值撞上真实值，真实踩过的坑）、容差公式 `max(0.061, |c|×1.1%)`、日期/时长豁免正则、QA 修订回路与超限降级、`route_node` 为什么用规则不用 LLM、每个节点的 `events` 追加
- **手写检验**：①白板画完整图拓扑（7 节点+2 回路+2 捷径+条件边条件）；②重写 `check_numbers`（抽数→剥日期时长→分域容差匹配）
- **面试钩子**："QA 不是 prompt 里写'请认真'，是确定性数字来源核验，能进 CI。"

### 4.6 归因：`analytics.py`（B 级）
- **读什么**：`drill_down()` 三件事——环比（两次单月查询）、维度贡献分解（prev/cur 对齐+delta 排序）、月度序列；全部 SQL 计算，LLM 零参与
- **自测**：为什么"为什么下滑"的数字必须代码算？（可复算；LLM 只解读不产数——质检才有据可依）

### 4.7 RAG：`example_store.py`（B 级）
- **读什么**：TF-IDF 字符二元组实现（中文短问句适配）、双后端同接口、种子样例与 DSL 词表共用一套常量
- **自测**：为什么默认不用向量检索？（确定性+零下载+"够用最简"；同接口可切）

### 4.8 评测：`eval/runner.py`（B 级）
- **读什么**：`judge_query` 的结果集规范化（排序+4 位小数）与 **top-k 语义等价**、四类判分、消融开关实现
- **自测**：为什么执行准确率比"SQL 相似度"硬？（结果对不对可比，SQL 写法无唯一）

### 4.9 API/前端/MCP（C 级）
- 知道：SSE 三类消息（node_done/event/final）、任务 JSONL 追加与回放、MCP 三工具与传输无关的 `core.py` 设计

## 7. 面试场景划重点

### 7.1 两分钟项目介绍（背熟这个骨架，用自己的话填）

> 场景一句话（ChatBI 对标腾讯云/瓴羊）→ 架构一句话（LangGraph 七节点流水线，确定性/不确定性分层）→ 三个亮点各一句（NL2DSL2SQL 白名单编译 / 数值确定性+质检闭环 / 拒答与行级权限）→ 数字收尾（真实模型 33 条评测 100%，消融证明质检闭环价值 93.9%→100%）。

### 7.2 追问树（面试官的典型路径与你的落点）

```
"介绍一下项目"
 ├─ 为什么多 Agent 不用一个循环？→ 失败域隔离/差异化重试/质检独立性（INTERVIEW Q1）
 ├─ 为什么不直接 NL2SQL？→ 安全/可控/口径/权限注入点（Q2）★最高频
 ├─ 幻觉怎么处理？→ 源头不产数→逐数核验→打回重写→降级徽章（Q7）★带消融数字
 ├─ 数字错了算谁的？→ 确定性核验可进 CI；语义核验是概率的（Q8）
 ├─ 注入怎么办？→ 四层防御+测试锚点（Q10）
 ├─ 权限怎么设计？→ 编译期注入，为什么不做 SQL 改写（Q11）★体现架构理解
 ├─ 失败重试？→ 两条回路+超限降级不吞异常（Q12）
 ├─ 评测怎么建的？→ 执行准确率+top-k 等价+消融（Q14）
 ├─ 和 DB-GPT/Vanna 比创新？→ 模式不新，质量门是增量（Q15）★诚实框架
 ├─ 踩过最深的坑？→ 百分比域跨域误配（Q16）★真实细节
 └─ "这是你自己写的吗？"→ 坦然版话术（本文第 0 节）+现场画图/改代码
```

### 7.3 高危问题与诚实答法

| 问题 | 诚实且加分的答法 |
|---|---|
| "有真实用户吗" | "还没有生产流量。数据是固定种子生成的模拟数据（可复现，内置归因故事信号）；场景对标在售商业产品；接生产数仓只需 DSL 编译器换 target" |
| "评测集自己建的，gold 对吗" | "gold SQL 手写、对固定种子数据、逐行比对判定——结论是'在此基准上 100%'，不是通用声明。评测集会随功能演进持续加条目" |
| "AI 写的吧" | 坦然版话术 + 主动提出"现场画状态机/现场改一处逻辑演示" |
| "为什么 p95 要 114 秒" | "p95 由归因题的审校修订循环主导——这正是质量换延迟的旋钮，轻量问题 2 次 LLM 调用 10 秒内" |

### 7.4 每个模块的"钩子句"（讲项目时抛出来引深挖）

- 编译器："LLM 永远碰不到物理表名。"
- 沙箱："就算全绕过，连接也是物理只读的。"
- 质检："叙述里每个数字我都能告诉你在结果集的第几行。"
- 拒答："火星区域不会得到一个很自信的错误答案。"
- mock："CI 永远绿，因为模型质量单独用评测集量。"
- 消融："我系统里每个组件，都有被删掉也能量出损失的证明。"
