# ADR：多轮指代消解（追问继承上一轮查询骨架）

> 状态：已实现（2026-10-28）｜实现：app/context.py + api/main.py 接线 + tests/test_followup.py（10 项）
> 全量测试 67 项全绿（57 既有 + 10 新增）；`FOLLOWUP_ENABLED` 默认 False，关闭时逐字零行为变化

## 1. 我为什么做指代消解

真实 BI 对话里追问占三分之一以上："上月华南毛利率"之后必来"那华北呢""换成电商呢"。当前架构每问都是独立单轮——追问会被当新问题重新走澄清（体验断裂）。多轮消解让 Agent 记住对话的"查询骨架"。

## 2. 设计决策

### 2.1 只存"上轮原始问题"，不存对话历史
- **决策**：会话上下文 = session_id → 上一轮（改写后的）完整问题，一行字符串。
- **备选与放弃**：①存完整对话历史——隐私面大、且追问只需要骨架；②存上轮 DSL 全量——追问可能换维度，DSL 补丁逻辑比问题文本替换复杂得多。
- **后果**：跨进程重启丢上下文——接 memomind 式持久化列为扩展。

### 2.2 追问判定是保守规则：判不出就当独立问题
- 短句（≤16 字）+ 追问句式（那X呢/换成X/改成X/X呢）+ 实体在词表内 → 追问。三者缺一不可。
- **误判方向被刻意设计成"保守"**：把追问误判成独立问题，走澄清反问（现有机制兜底）；反过来把独立问题误判成追问，会答错对象——宁可体验降级不可答错。

### 2.3 实体归一：通用后缀剥离
- 词表按维度类型组织（region/channel/category），但用户说"直播渠道"而词表只有"直播"——**先剥离通用后缀（渠道/品类/地区）再查词表**，替换时用完整实体（把上轮的"直播"替换成"直播渠道"）。
- 这个归一是我测试跑出来的：第一版"换成直播渠道"判定 False，排查发现贪婪匹配把"呢"吃进实体名，修完又暴露后缀问题——**两层归一（语气词剥离 + 通用后缀剥离）都是测试驱出来的**。

### 2.4 接线：API 层前置改写，不进图
- **决策**：消解在 `/api/ask` 入口做（改写 question 后再入图），事件流插一条 followup 说明。
- **备选与放弃**：图内加节点——LangGraph 拓扑改动大，且改写本质是"输入预处理"不是"Agent 决策"。
- 开关 `FOLLOWUP_ENABLED` 默认 False + `session_id` 可选字段：留空视为独立单轮，老客户端零影响。

## 3. 边界

- 词表换域要补（与 memomind 意图映射同款维护面）。
- 只支持实体替换型追问；"环比怎么样"这类指标切换型追问需要 metric 槽位填充——列为下一版。
- 会话上下文进程内——多 worker 部署要粘性会话或外置存储。
